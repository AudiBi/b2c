# Intégrations externes

Phases 3 à 9. Une intégration n'est dite **active** que si elle a été exercée avec un service réel.

| Intégration | État | Détail |
|---|---|---|
| PostgreSQL 17 | ✅ active | Conteneur Docker de développement ; rôles `b2c_migrator` / `b2c_app` |
| Redis 7 | ✅ active | Limitation de débit et verrouillage des connexions ; échec « fermé » sur les routes d'authentification |
| E-mail (SMTP) | ◐ **active en développement seulement** (**messages HTML de la marque** : logo, titre, bouton d'action avec lien de secours, pied de page, trois langues, version texte brut jointe ; le logo est une **image intégrée** au message, sans serveur d'images) | Livraison vérifiée vers Mailpit (aussi dans la recette navigateur, qui lit les messages) ; aucun fournisseur de production configuré. Depuis la phase 7, les notifications passent par une **file en base** (outbox) avec **nouvelles tentatives espacées** (1, 5, 30, 120 min) puis échec visible et relance par le personnel ; les e-mails d'authentification restent envoyés directement. Textes en FR/HT/EN (créole à relire) |
| Navigateurs de test | ✅ | Chromium de Playwright ; Microsoft Edge en repli. Pas de Firefox ni Safari |
| Pièces jointes (factures, photos) | ✅ disque local (défaut) | Dossier `FILES_DIR`, par défaut `./.data/files`, choisi par `STORAGE_DRIVER=disk` |
| Stockage objet compatible S3 | ◐ **active contre SeaweedFS (développement) seulement** | Adaptateur `S3Storage` (`STORAGE_DRIVER=s3`, client officiel `@aws-sdk/client-s3`) : 10 tests contre un **vrai SeaweedFS** en Docker (`npm run test:s3` après `docker compose -f docker/compose.dev.yml --profile storage up -d seaweedfs`) : octets restitués à l'identique (les 256 valeurs d'octet, 3 Mio), objet vide, noms accentués, suppression idempotente, bucket absent et mauvais identifiants refusés franchement, parcours API complet (téléversement, lien signé, suppression réelle dans le bucket). **Jamais exercé contre AWS S3, Cloudflare R2 ou un autre fournisseur** : à rejouer avec un compte de test de ce fournisseur avant de l'utiliser. SeaweedFS remplace MinIO (image introuvable) ; le compose le lance avec `-s3.autoCreateBucket=false`, car il créait sinon silencieusement un bucket absent, contrairement à S3 (relevé par un test). Le bucket se crée par `npm run s3:init` (développement uniquement) ; en production, par l'hébergeur |
| Authentification à deux facteurs (TOTP) | ✅ active | Algorithme standard (RFC 6238) : compatible avec toute application d'authentification ; l'implémentation reproduit les vecteurs de test officiels du RFC (annexe B) ; **aucune application réelle de téléphone n'a été essayée** |
| SMS | ⛔ **retiré du produit** | Décision : plus de canal ni de préférence SMS (interface, API, préférences). Aucun SMS n'est envoyé |
| WhatsApp Business | ❌ non configuré | Aucun compte. Une notification WhatsApp demandée par le client est enregistrée « ignorée — canal non configuré » (`CHANNEL_NOT_CONFIGURED`) ; **rien n'est envoyé ni simulé** |
| Paiement en ligne (cartes) | ❌ non configuré | Aucun prestataire choisi : **aucun paiement en ligne n'est proposé** (`/v1/me/payment-options` répond `online: false`). Le client paie en espèces auprès du personnel, ou **déclare** un virement / paiement mobile qu'un agent valide à la main après vérification. Un point d'entrée de **confirmation signée** (`POST /v1/webhooks/payments/:entreprise/:prestataire`, HMAC-SHA256 horodaté, rejeu sans effet) existe mais **n'est actif que si `PAYMENT_WEBHOOK_PROVIDER` et `PAYMENT_WEBHOOK_SECRET` sont définis** ; il n'a été exercé qu'avec un émetteur simulé par les tests (aucun prestataire réel), et il n'y a **pas d'adaptateur** de prestataire (création de paiement, remboursement chez le prestataire) |
| Code de remise (OTP) | ◐ **portail seulement** | Généré par le client dans son espace ; **aucun envoi par SMS ou WhatsApp** (aucun prestataire) |
| Cartographie / itinéraires / GPS | ❌ aucun | Ni carte, ni optimisation de tournée, ni position du livreur ; adresses saisies par les clients |
| Transporteurs aériens / maritimes | ❌ non configuré | Aucun suivi automatique : départ et arrivée des lots sont **saisis par le personnel** (phase 6) ; aucune date prévue, aucune position |
| Génération de PDF (manifestes, factures, reçus) | ✅ active | Bibliothèque `pdfkit` (locale, sans service externe) ; tests : le document est un PDF valide, sans contrôle visuel automatisé |
| Lecteur de codes-barres | ✅ par clavier | Un lecteur qui « tape » le code puis Entrée suffit (champ focalisé) ; testé par saisie simulée, **pas avec un lecteur matériel** ; pas de scan par caméra |
| Sites marchands (Amazon, Walmart…) | ❌ aucune | Aucune intégration n'est prévue ni simulée |
